# Помощник техподдержки на FastAPI

Учебный HTTP-сервис вызывает OpenAI через Responses API, проверяет запросы,
поддерживает потоковую выдачу. В этом снимке непотоковая ручка дополнена инструментом чтения заявки. Для базы использованы
структура FastAPI, ASGI-тесты и Redis из снимка `ai-tools-and-links/m3_b5`.

## Запуск

Нужны Python 3.12, uv и ключ OpenAI. Скопируйте `.env.example` в `.env`, заполните
`OPENAI_API_KEY` и задайте разные случайные `DEMO_TOKEN_A` и `DEMO_TOKEN_B`.

```bash
uv sync
uv run uvicorn app.main:app
```

В OpenAPI на `http://127.0.0.1:8000/docs` укажите учебный bearer-токен. Пример
тела для `POST /chat`:

```json
{"messages":[{"role":"user","content":"Как восстановить пароль в SaaS?"}]}
```

`POST /chat/stream` принимает то же тело и передаёт SSE-события
`delta`, `usage`, `done` либо `error`. В `POST /chat` флаг `cache` сохранён для совместимости со схемой из М2, но чтение актуальных статусов обходит кеш ответов. `GET /health` проверяет процесс, `GET /ready` также проверяет Redis при
наличии `REDIS_URL`. Команда `docker compose up --build` запускает Redis вместе с API.

Учебные токены заменяют аутентификацию на семинаре. В прикладном сервисе личность
пользователя берётся из проверенной сессии или доверенного поставщика идентификации.

```bash
uv run ruff check .
uv run pytest -q
```

В тестах ответы API подставляются в HTTP-транспорт. Ключ и Redis не требуются.

## Приращение для вызова инструментов

Этот снимок продолжает предыдущий FastAPI-сервис. В `POST /chat` добавлен
инструмент `get_ticket_status`. Профиль A видит `T-1042` и `T-1043`, профиль B
видит `T-2042`. Для неизвестной и недоступной заявки инструмент возвращает
одинаковый ответ. Модель не получает токены и не может передать идентификатор
пользователя в аргументах функции.

Вызовы `POST /chat` в этом снимке проверяют актуальный статус и обходят кеш
ответов. Потоковая ручка передаёт текстовый ответ без инструмента. Чтобы совместить
инструменты со стримингом, службе нужен собственный цикл по событиям Responses.
