# Локальная операция чтения заявки через MCP

Пример для показа преподавателем. Локальный клиент запускает сервер через stdio и один раз вызывает `get_ticket_status("T-1042")`.

## Запуск

Из этого каталога на Python 3.12:

```bash
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python client.py
.venv/bin/python -m pytest -q
```

Ожидаемый вывод клиента:

```json
{"ticket_id": "T-1042", "status": "in_progress"}
```

## Данные и доступ

Все заявки синтетические. Профиль support-a фиксирован в локальном серверном модуле. T-1042 доступна этому профилю, T-2042 относится к support-b. Чужая и отсутствующая записи дают одинаковый `ticket_unavailable`. Модель или клиент не передают профиль аргументом инструмента.

В основном сервисе профиль определяется по аутентификации. Этот отдельный показ иллюстрирует локальный транспорт и схему одного инструмента. Запроса к LLM и настоящему источнику заявок здесь нет.

## Граница доступа

В stdio доверенный контекст задаётся при запуске процесса. При подключении удалённого MCP-сервера по Streamable HTTP проверяется авторизация соединения и доступ к каждой заявке. Передавать произвольный профиль через аргументы инструмента нельзя.

[Спецификация авторизации MCP](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization)

## Проверки

Тесты проверяют чтение, отказ, формат номера и настоящий обмен stdio с дочерним процессом. В протокольной проверке дополнительно сверяются список инструментов, схема аргументов и структурированный результат.

[Официальный Python SDK](https://github.com/modelcontextprotocol/python-sdk)
