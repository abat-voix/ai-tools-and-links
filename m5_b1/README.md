# Косинус, нормализация и порог поиска

Локальный пример показывает ранжирование на вручную заданных векторах. Нужен Python 3.12, внешних зависимостей, ключей и серверов нет.

## Запуск

Из этого каталога:

~~~bash
python3 search.py
python3 search.py --threshold 0.99
python3 -m unittest -v
~~~

При пороге 0.8 запрос refund_query возвращает refund_rules с оценкой около 0.98 и payment_methods с оценкой 0.8. При пороге 0.99 оба документа отбрасываются. Для outside_example при 0.8 результат пуст.

## Что проверить

Сначала сравнить скалярное произведение с косинусом. У длинного вектора [10, 10] произведение с [1, 0] больше, чем у [1, 0.1]. После нормализации выше ранжируется [1, 0.1], направление которого ближе к запросу. Этот случай есть в тесте.

Затем изменить порог и записать, какие документы пропали. Оценка сходства не является вероятностью правильного ответа. Порог 0.8 выбран для заданных координат и не переносится на настоящую embedding-модель.

## Как продолжить

В vectors.json все координаты заданы вручную. Названия документов иллюстрируют ожидаемую связь, но никакая модель не извлекала её из текста. Этот пример проверяет геометрию поиска.

Для проверки настоящей модели подготовить запросы и релевантные документы, получить их векторы одним совместимым способом и сравнить ранжирование. Получение эмбеддингов через API и загрузка корпуса показаны в [следующем снимке](../m5_b2/README.md). Здесь нет embedding-сервиса, дискового кеша или доказательства качества модели на тексте.
