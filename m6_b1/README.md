# Агент с циклом вызова инструментов

Отдельный небольшой пример показывает цикл модели без графового фреймворка. Он содержит CLI, три локальных инструмента и трассу шагов. Для последующего подключения настоящего поиска можно заменить реализацию `search_knowledge_base`.

## Что реализовано

| Часть | Файл | Поведение |
|---|---|---|
| Цикл | `app/services/agent_naive.py` | `run_agent(task, max_steps=6)` вызывает модель, выполняет инструменты и возвращает результат модели |
| Описания и диспетчер | `app/tools/naive_tools.py` | JSON Schema и словарь `DISPATCH` ограничивают доступный набор функций |
| Трасса | `app/services/agent_naive.py` | Имя инструмента, аргументы, сокращённый результат, длительность и доступный расход токенов |
| CLI | `scripts/run_naive_agent.py` | Обёртка над тем же циклом |

Инструмент `search_knowledge_base(query)` ищет в небольшом локальном словаре. `get_current_time(timezone)` возвращает время. `send_telegram_message(chat_id, text)` — учебная имитация без обращения к Telegram. Подтверждения человека перед действием в этом цикле нет.

## Быстрая проверка без ключа

Из каталога `m6_b1` на Python 3.12+ с `uv` выполните `uv run --locked pytest -q`. Тесты проверяют цикл с подставной моделью. Пример служит начальной точкой для работ 6.1 и 6.2.

## Запуск с моделью

```bash
uv sync --locked
test -f .env || cp .env.example .env
```

В `.env` заполнить `OPENAI_API_KEY`. Файл с ключом остаётся локальным. Пример использует OpenAI SDK напрямую, поэтому `.env` передаётся командой запуска.

```bash
uv run --locked --env-file .env python -m app.services.agent_naive \
  'Какие правила возврата электроники?' --trace
```

Агент вызывает Responses API. Модель по умолчанию — `gpt-6-luna`, режим рассуждения — `none`. Для `--model gpt-6.2-sol` и `--model gpt-6.2-astra` используется `low`. `--max-steps` задаёт лимит обращений, по умолчанию шесть.

## Что возвращается

При успехе функция возвращает `answer`, `steps` и `trace`. Исчерпание бюджета даёт `answer: null` и `error: "max_steps"`. Текущий CLI выводит сообщение об остановке, но завершает процесс с кодом 0 и при таком исходе. При автоматической проверке необходимо смотреть на результат функции или текст остановки.

Для разбора сравнить простой поиск и составной запрос, требующий времени, поиска и имитации отправки. Число и порядок вызовов выбирает модель, поэтому формулировка задания не гарантирует конкретную трассу. Данные трассы могут содержать текст задачи и аргументы, сохранять следует только учебные данные.

Для проверки стиля выполните `uv run --locked ruff check .`. Локальная сверка типов значений аргументов со схемой входит в задание 6.1.
