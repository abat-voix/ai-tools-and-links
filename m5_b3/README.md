# Ответ по базе знаний с источниками

Снимок продолжает чат-сервис с Qdrant. Добавляется путь RAG: вопрос преобразуется в вектор, поиск находит фрагменты, модель генерирует ответ, приложение формирует ответ ручки.

## Что добавилось

| Возможность | Файл | Назначение |
|---|---|---|
| RAG на LlamaIndex | app/services/rag.py | Индекс, запрос к модели и итоговый порог |
| RAG на клиентах API | app/services/rag_baremetal.py | Сопоставление шагов без фреймворка |
| HTTP-контракт | app/routers/rag.py | POST /rag/query |
| Корпус | data/rag-block-03/ | Документы для поиска |
| Прогон интеграций | scripts/verify_rag.py | Одноразовые коллекции, поиск и генерация |

При старте `app/main.py` индексирует локальный корпус, если коллекция пуста, затем подключает `RAGService`. Непустая коллекция подключается без повторной индексации. Для отдельного эксперимента укажите новое `RAG_COLLECTION`. Для обновления текущей коллекции используйте `POST /documents/reindex` (практика 5.5).

## Куда смотреть

`RAGService.answer` сначала получает найденные фрагменты и сравнивает лучший score с `RAG_SCORE_THRESHOLD`. При слабой или пустой выдаче сервис возвращает отказ до обращения к модели. Если порог пройден, найденные фрагменты передаются модели и используются как источники ответа. `confident` описывает прохождение порога соседства.

Контракт ответа:

~~~json
{
  "answer": "Текст ответа либо сообщение об отсутствии ответа",
  "top_score": 0.57,
  "confident": true,
  "sources": [{"id": 1, "file_name": "billing_refunds.md", "page": null, "score": 0.57, "snippet": "Фрагмент"}]
}
~~~

Числа иллюстрируют форму. Наличие sources показывает найденные фрагменты, а соответствие утверждений этим фрагментам проверяется отдельно.

## Быстрый старт

Нужны Python 3.12, uv, Docker и ключ OpenAI. Команды выполнять из этого каталога. При первом запуске создать .env из .env.example, заполнить LLM__OPENAI_API_KEY. Существующий .env сохранить.

~~~bash
uv sync --locked
test -f .env || cp .env.example .env
docker compose up -d --wait qdrant
QDRANT_URL=http://localhost:6333 uv run --locked uvicorn app.main:app --reload --port 8000
~~~

При построении индекса выполняются платные запросы эмбеддингов. Генерация использует Responses API и модель из `RAG_LLM_MODEL`. По умолчанию это `gpt-6.2-sol`.

## Проверить HTTP-ответ

~~~bash
curl -s -X POST http://localhost:8000/rag/query   -H "Content-Type: application/json"   -d '{"question":"За сколько дней можно вернуть деньги за подписку?"}'
~~~

Ожидаются поля `answer`, `top_score`, `confident` и `sources`. При недоступном индексе ручка возвращает 503; пустой вопрос даёт 422. Для проверки отсутствия ответа выбрать вопрос вне корпуса и проверить фактическую оценку: один только «нерелевантный» вопрос не гарантирует низкий score.

## Проверить поиск и генерацию

~~~bash
QDRANT_URL=http://localhost:6333 uv run --locked python scripts/verify_rag.py
~~~

Скрипт использует QDRANT_URL и, при необходимости, QDRANT_API_KEY. Ключ OpenAI берётся из LLM__OPENAI_API_KEY. Он создаёт коллекции с уникальным префиксом, проверяет LlamaIndex, фильтры, повторное подключение и удаляет экспериментальные коллекции. Дополнительный гибридный путь требует fastembed.

## Проверки без API

~~~bash
uv run pytest tests/test_rag.py -q
uv run pytest -q
~~~

Тесты ручки подменяют сервис. Тесты format_result проверяют итоговый порог. Полный сетевой прогон выше дополнительно проверяет настоящие Qdrant и модель. QDRANT_TEST_URL используется только сетевыми тестами хранилища и не меняет адрес verify_rag.py.

## Полный compose

В .env заполнить ключ модели, BOT_TOKEN, BOT_ADMIN_IDS, ADMIN_TOKEN, INTERNAL_TOKEN и ADMIN_CHAT_ID. Для отдельных экземпляров задать разные собственные токены.

~~~bash
docker compose up -d --build
docker compose exec app alembic upgrade head
~~~

В сети compose Qdrant доступен по http://qdrant:6333. Для локальных Python-команд использовать localhost:6333.
