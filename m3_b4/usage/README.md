# Проверка стоимости одной попытки

Самодостаточный пример на стандартной библиотеке Python 3.12. Приложение передаёт счётчики Responses usage и тарифы за миллион токенов. Расчёт использует Decimal и возвращает стоимость по категориям и итог.

Из этого каталога:

~~~bash
python3 cost.py
python3 -m unittest -v
~~~

В первом JSON-примере взяты числа из слайдов Б3.4: 12 000 входных токенов, 4 000 чтения, 7 000 записи, 200 выходных. Обычный вход равен 1 000. С учебными тарифами $1 / $0,1 / $1,25 / $5 получается **$0,01115**.

Во втором примере те же 7 000 записей распределены на 3 000 токенов с TTL 30 минут и 4 000 с TTL 12 часов. При явно переданных тарифах $1,25 и $2,5 за миллион итог с выходом равен **$0,01615**. Это дополнительное учебное распределение. Названия полей соответствуют текущей документации Responses.

Если детализации срока записи нет, нужен явно переданный единый тариф cache_write. Если она есть, сумма ttl_30m_tokens и ttl_12h_tokens должна равняться cache_write_tokens; суммарная запись повторно не начисляется. reasoning_tokens входит в output_tokens и повторно не добавляется.

Отсутствие обязательных счётчиков, несовместимые суммы и отсутствие тарифа для ненулевой категории приводят к ошибке. Попытка без usage имеет неизвестный расход. Нулевую стоимость ей эта функция не назначает.

Цены учебные. Приложение выбирает реальные ставки под модель, режим, дату и валюту. Инструменты поставщика, налоги, скидки, округление счёта и попытки с неизвестным usage требуют отдельного учёта. Пример не подключается к OpenAI или Phoenix и не сверяет итог с реальным счётом.

[Официальная документация по кешированию и учёту токенов](https://developers.openai.com/api/docs/guides/prompt-caching)

Для счётчиков без `cache_write_tokens` расчётчик использует ноль записи. Такой вызов допустим, только когда выбранный режим API действительно не тарифицирует запись отдельно. При неизвестной форме usage совместимость проверяет вызывающий слой. Сокращённый HTTP-агрегат учебного сервиса не содержит всех полей, поэтому для расширенного расчёта нужен исходный usage каждой попытки.
